# Платформа основателя: вход по логину, пользователи, учёт

Сайт отчётов — статический (GitHub Pages), поэтому логины, блокировки и учёт работы живут
в бесплатной базе **Supabase**. Серверного кода нет: вся логика — функции в базе (`supabase/schema.sql`),
сайт вызывает их по HTTPS с публичным ключом. Таблицы для публичного ключа закрыты, пароли хранятся
как bcrypt-хэши, сессии живут 60 дней.

## Настройка (один раз, ~10 минут)

1. Зайдите на https://supabase.com → **New project** (регион любой, пароль базы запишите, он больше не нужен).
2. В проекте откройте **SQL Editor** → **New query**, вставьте содержимое файла `supabase/schema.sql` → **Run**.
3. Откройте **Project Settings → API**: скопируйте **Project URL** и ключ **anon public**.
4. В репозитории откройте `public/platform.json` и впишите:
   ```json
   { "url": "https://xxxx.supabase.co", "anonKey": "eyJ..." }
   ```
   Сделайте commit и push — сайт пересоберётся сам.
5. Откройте `https://<ваш сайт>/admin.html`. При первом запуске платформа предложит **создать основателя**:
   задайте свой логин и пароль. Это единственный аккаунт с доступом к панели.

Пока `platform.json` пустой, сайт работает как раньше — без входа.

## Как это работает

- **Сайт отчётов** (`index.html`): при открытии показывает экран входа. Пользователь вводит логин
  и пароль, выданные вами. Сессия запоминается в браузере; «Выйти» в шапке.
- **Панель** (`admin.html`): вход только по логину основателя. Здесь:
  - создать пользователя (логин, имя, заметка; пароль генерируется и показывается один раз — скопируйте
    и отправьте человеку вместе со ссылкой);
  - заблокировать / разблокировать (сессии заблокированного сразу завершаются);
  - выдать новый пароль, изменить имя и заметку, удалить;
  - у каждого пользователя: устройства (система и браузер, первый и последний вход), книги Excel,
    листы-отчёты, часы работы; последние действия.
- **Учёт**: пока вкладка сайта открыта, раз в минуту прибавляется минута работы устройству;
  скачивание книги — «книга» (+ по листу на класс), загрузка журнала — «журнал».
- Один человек на нескольких устройствах виден как несколько строк устройств.

## Безопасность

- Публичный ключ не даёт доступа к таблицам — только к функциям, каждая проверяет сессию и роль.
- Пароли никогда не хранятся в открытом виде; при неверном пароле база задерживает ответ.
- Основателя нельзя заблокировать или удалить из панели; второго основателя создать нельзя.
- Если потеряли пароль основателя: в SQL Editor выполните
  `update app_users set pass_hash = crypt('НОВЫЙ_ПАРОЛЬ', gen_salt('bf')) where role = 'owner';`

```bash
node test/mock-platform.mjs      # имитация базы на 127.0.0.1:4711
# в public/platform.json временно: { "url": "http://127.0.0.1:4711", "anonKey": "dev" }

```
